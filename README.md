# ToyC 教学编译器

把 ToyC 源代码编译为 RISC-V64 汇编的 C++17 基础实现。包含词法分析、语法分析、语义检查、中间代码、基础优化和代码生成。源代码中的注释用于帮助阅读和答辩。

**提交截图中的词法分析作业，请先看 [希冀平台提交说明](SUBMISSION.md)**：分支为 `main`，使用 `make` 构建，调用 `./compiler -token`。默认模式同样输出 token；完整编译模式使用 `-S`。

## 先跑一个最小例子

编译只需要支持 C++17 的编译器和 Make，没有第三方库依赖：

```sh
make
./compiler -S -O1 examples/simple.c -o /tmp/simple.s
```

输入 `examples/simple.c`：

```c
int main() {
    int a = 2 + 3;
    return a;
}
```

输出 `/tmp/simple.s` 是汇编文件。它经过 RISC-V 工具链汇编、链接并运行后，`main` 返回 5；这段源程序没有调用输出函数，所以不会自动向终端打印 5。

生成的实际汇编包含建立和恢复栈帧的代码，不能仅看是否出现 `li a0, 5` 来判断整个程序是否正确。

## 七个 C++ 模块

| 文件 | 输入 → 输出 | 作用 |
| --- | --- | --- |
| `main.cpp` | 命令行和文件 → 选择的结果 | 读取输入，依次调用各模块，统一处理错误 |
| `lexer.cpp` | 字符 → token 流 | 识别单词、整数、运算符，跳过注释 |
| `parser.cpp` | token 流 → AST | 按文法用递归下降建立语法树 |
| `semantic.cpp` | AST → 绑定变量并核验后的 AST | 检查作用域、类型、参数、返回语句等 |
| `ir.cpp` | AST → 三地址形式的 IR | 将表达式和结构化语句变成运算、标签和跳转 |
| `optimizer.cpp` | IR → 优化后的 IR | 常量传播、常量折叠、不可达代码与无用临时值删除 |
| `codegen.cpp` | IR → RISC-V64 汇编 | 分配栈槽，生成指令、函数调用及返回代码 |

`.h` 文件声明接口；`token.h`、`ast.h`、`ir.h` 分别定义 token、语法树和中间表示。所有模块最终编译为同一个 `compiler` 可执行程序。

建议从 `main.cpp` 阅读调用流程，再按表格顺序阅读各个模块。

## 命令行

```sh
# 兼容原词法作业：默认模式和 -token 都输出 token
./compiler -token < examples/demo.c

# 输出语法树；会先做语义检查
./compiler --ast examples/simple.c

# 查看优化前后中间代码
./compiler --ir -O0 examples/simple.c
./compiler --ir -O1 examples/simple.c

# 输出优化前后的汇编
./compiler -S -O0 examples/simple.c -o /tmp/simple.O0.s
./compiler -S -O1 examples/simple.c -o /tmp/simple.O1.s

# 只检查词法、语法和语义；成功时不输出内容
./compiler --check examples/course_sample.c
```

不提供输入文件时读取标准输入；不提供 `-o` 时写标准输出。默认关闭优化，`-O1` 开启基础优化。这些模式是本项目的接口，最终平台的编译器调用协议若有另外要求，需要适配。

编译错误返回 1，命令行参数错误返回 2。错误及行列位置写标准错误，不混入正常输出。编译失败时，不覆盖已有的输出文件。

## 支持的语言功能

- `int`、`void` 函数，`int` 参数，递归及嵌套函数调用。
- 局部变量、`const int`、初始化、赋值、嵌套作用域和变量遮蔽。
- 语句块、空语句、表达式语句、`if/else`、`while`、`break`、`continue`、`return`。
- 一元 `+ - !`；算术 `+ - * / %`；比较 `< > <= >= == !=`；逻辑 `&& ||`。
- `&&`、`||` 用控制流实现短路求值，结果为 0 或 1。
- 十进制整数、ASCII 标识符、空白、单行及非嵌套块注释。
- 内置运行库接口：`int getint()`、`int getch()`、`void putint(int)`、`void putch(int)`。

语义检查包括：重复定义、未声明变量、修改常量、调用尚未定义的函数、参数数量不符、将 void 用作整数、返回语句类型不符、在循环外使用 break/continue、缺少合法的 `int main()`。

按截图约束，函数需在调用前定义，当前函数支持调用自身。参数和函数最外层局部变量处于同一作用域。

`examples/functions.c` 演示递归、循环、break/continue 和输出。正确运行时打印：

```text
120
8
```

## 词法输出与文法细节

输入 `int a = -1;` 的 token 输出为：

```text
0:'int':"int"
1:Ident:"a"
2:'=':"="
3:'-':"-"
4:IntConst:1
5:';':";"
```

整数不加双引号；其余 token 内容加双引号；序号从 0 开始，不输出 EOF token。`main`、`sum`、`putint` 都是普通标识符。

截图中的整数正则含可选负号，但样例把 `b = +a - -1;` 的两个负号分别输出。本项目遵循样例：负号独立成 token，语法阶段区分一元负号和二元减法。

整数按 `0|[1-9][0-9]*` 匹配，因此 `012` 会拆成 0 和 12，随后在表达式中被语法分析拒绝。纯词法模式保留数字文本；完整编译模式检查有符号 32 位字面量范围，支持 `-2147483648`。

截图的修订文法把六种比较运算放在同一层，按左结合解析。因此 `2 == 2 < 2` 按 `(2 == 2) < 2` 处理。若教师发布了新文法，应以新版本为准。

未闭合块注释、文法外字符会报告词法错误。截图没有规定错误输出协议，这里的诊断格式是本项目的约定。

## 优化与后端设计

`-O1` 实现：

1. 在基本块内传播已知常量，不把某条路径的值直接传播到多前驱的标签处。
2. 对常量算术、比较和一元表达式折叠；遇到溢出、除零或 `INT_MIN / -1` 时保留原运算。
3. 简化常量条件跳转，按控制流可达性删除不可达代码。
4. 删除无人使用的纯计算临时结果，保留有潜在副作用的函数调用。

后端以栈槽存放局部变量和临时值，没有实现寄存器分配；整数用 32 位指令计算。前八个整数实参使用 a0–a7，其余放在栈上；维护 16 字节栈对齐并保存恢复 ra、s0，依据 [RISC-V 调用约定](https://riscv-non-isa.github.io/riscv-elf-psabi-doc/#_integer_calling_convention)。

大栈帧会使用寄存器计算地址，避免栈偏移超过 12 位立即数范围。条件跳转通过邻近标签和无条件跳转组合，避免较大分支体超过条件分支范围。

## 测试

无需额外 Python 包的测试：

```sh
make test
```

包括词法格式、题目 208 个 token 样例的关键位置、运算符优先级、错误检查、常量折叠、不可达代码、文件接口和大栈偏移。

可选的机器码端到端测试：

```sh
python3 -m venv /tmp/toyc-test-env
/tmp/toyc-test-env/bin/python -m pip install -r tests/requirements.txt
/tmp/toyc-test-env/bin/python tests/test_riscv.py ./compiler
```

若当前 Python 环境已安装测试依赖，也可以使用 `make test-riscv`。它通过 Zig/LLVM 真正汇编和链接 RV64 ELF，再用 Unicorn 执行机器码；覆盖优化开关、递归、短路、输入输出、嵌套循环、260 个参数、大栈帧、长条件分支，以及与独立 C 编译器双向调用的兼容性。还会将 30 个算术表达式的执行结果与主机 C 编译器生成的程序比较。

端到端测试使用私有 ecall 实现测试 I/O，不是 Linux 系统调用接口，也不是课程平台运行库。部分 macOS 沙盒会禁止模拟器映射执行内存，需要在允许模拟器运行的终端环境执行。

## 在 Linux / QEMU 环境运行

若环境提供 RISC-V64 GNU 工具链、相应静态 C 运行库及 QEMU，可使用以下命令；课程平台提供专用运行库时应换成平台版本：

```sh
./compiler -S -O1 examples/functions.c -o /tmp/functions.s
riscv64-linux-gnu-gcc -static /tmp/functions.s runtime/io.c -o /tmp/functions.rv64
qemu-riscv64 /tmp/functions.rv64
```

`runtime/io.c` 是基于标准 C 输入输出的示例运行库，不参与构建编译器本身。这组 Linux / QEMU 命令尚未在本机执行；本机使用上面的 LLVM 汇编链接和 Unicorn 机器码执行测试。

## 当前边界和课程交付事项

这是可继续开发的教学基础版。未支持截图文法外的数组、指针、浮点数、字符串、全局变量、for 语句、函数原型和赋值表达式。

尚未做全路径返回值检查或未初始化变量检查。当前为函数末尾生成返回 0 的保底出口；测试程序应在 int 函数需要的路径上明确返回。读未初始化变量、整数溢出及除零不属于可据以证明正确性或加速比的测试。

没有做寄存器分配、SSA、循环优化或官方性能测评。基础优化能改变生成代码，但不据此声称达到课程平台的性能要求。

课程的修订文法、完整语义细则、运行库签名、构建调用参数、测评和计时脚本还需与教师发布版本逐项核对。正式提交还需要真实测试记录、成员贡献、AI 使用说明和学院模板报告；这里的代码和测试不能替代这些材料。
